# ADR-0007: Least-privilege probes and runner-side sanitization

- Status: accepted, 2026-10-10

## Context

Diagnostic probes read real warehouse data, including per-person compensation and identifiers, and their output feeds incident summaries generated by an LLM (review finding I9).

## Decision

- Probe SQL must pass a sqlglot guard (exactly one SELECT or WITH query, no DDL, DML, COPY, ATTACH, PRAGMA or file-reading table functions; `read_parquet` only under the snapshot directory).
- Locally, probes run on a separate DuckDB connection opened with `read_only=True`. On BigQuery they run as the impersonated `datatrust-prober` service account (read-only roles), with a dry run and `maximum_bytes_billed` on every query.
- Probes return aggregates and at most five sample keys. The runner pipes results through `rca sanitize` (the TypeScript sanitizer) before upload: identifiers become HMAC-SHA256 tokens with an entity prefix, PII and compensation values are dropped, free text is dropped and error text is reduced to an error class name. This is pseudonymization, not anonymization.
- The Worker re-runs the detectors (`findUnsanitized`) on every payload and rejects anything untokenized.

## Consequences

Even a guard bypass cannot write, raw identifiers never reach R2 or D1, and `test_no_pii_in_prompts.py` checks that no generated name, email, phone number, birth date or salary reaches a prompt.
